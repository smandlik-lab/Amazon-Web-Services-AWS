AWS Basic Architecture

Cloud Architecture Cheat Sheet
This architecture shows a practical AWS application flow: users reach the application through DNS and CDN services, API traffic is routed through API Gateway, backend workloads run on compute services, asynchronous work is handled through SQS, data is stored in relational or NoSQL databases, and operational services provide storage, monitoring, logging, access control, and identity management.

Key AWS Building Blocks

🌐

DNS & CDN

  • Amazon Route 53
  • CloudFront
  • Static files & images
  • Global content delivery
Goal: Direct users to the application and deliver static content efficiently.
🚪

API Gateway

  • Request routing
  • Authentication
  • Rate limiting
  • Throttling
Goal: Provide a controlled entry point for backend APIs.
⚙️

Compute Layer

  • EC2 — virtual servers
  • ECS — container workloads
  • Lambda — serverless functions
  • Choose compute by workload
Goal: Run application services using the appropriate compute model.
📨

Async Processing

  • Amazon SQS
  • Decouple services
  • Process background requests
  • Improve resilience
Goal: Move long-running or background work out of synchronous API requests.
🗄️

Data Layer

  • Amazon RDS
  • Amazon DynamoDB
  • Relational data
  • NoSQL data
Goal: Store application data using the database technology that fits the workload.
🪣

Object Storage

  • Amazon S3
  • Images
  • Videos & audio
  • Large files
Goal: Store durable media and large objects separately from application compute.
📊

Monitoring

  • Amazon CloudWatch
  • Logs
  • Metrics & monitoring
  • Operational visibility
Goal: Observe application health and identify operational issues.
🔐

Identity & Access

  • AWS IAM
  • Access control
  • Identity management
  • Least-privilege permissions
Goal: Control who and what can access AWS resources.

🔄 Typical Request Flow

User → Route 53 → CloudFront → API Gateway → Compute → Database/Storage. For background processing, the application can place work on SQS and process it asynchronously.

💡 Architecture Mindset

Think of AWS as a collection of specialized building blocks. Design the flow around scalability, security, resilience, observability, and the specific needs of each workload.
